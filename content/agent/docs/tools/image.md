The `image` group contains `generate_image`, which produces a new image from a
text prompt using the session's image-capable provider. It is not active by
default — activate it with `load_tools image`.

| Tool | What it does |
|---|---|
| `generate_image` | Generate an image from a text prompt; the result is displayed inline in the client exactly like `display_image` |

## Arguments

| Argument | Meaning |
|---|---|
| `prompt` | What to depict (required). Photographic results come from photographic language (lens, lighting, film, camera detail); illustration phrasing produces illustration |
| `model` | Explicit image model id (e.g. `gpt-image-1`, `glm-image`). Optional — when omitted, the provider's catalog image models are picked by priority |
| `size` | Output canvas: `auto`, `1024x1024`, `1024x1536`, or `1536x1024` |
| `quality` | Render quality hint: `auto`, `low`, `medium`, or `high` |
| `output_format` | Encoded format of the returned image: `png`, `jpeg`, or `webp` |
| `background` | `auto`, `opaque`, or `transparent` (transparent requires png/webp) |
| `alt` | Alt text for the displayed image |
| `seed` | Optional seed for reproducible generation (fal.ai only) |

```json
{ "name": "generate_image", "arguments": { "prompt": "a lighthouse at dusk, 35mm film grain", "size": "1024x1024" } }
```

## Providers & model selection

Generation runs against the session's account. Three adapters are supported:

- **OpenAI Images** — OpenAI-compatible endpoints (`gpt-image-*`).
- **z.ai / Zhipu GLM** — `glm-image`.
- **fal.ai** — flux and other hosted image models; accepts the `seed` knob.

Model selection is catalog-driven: an explicit `model` argument always wins;
otherwise the provider's verified image models (`supports_image_output`) are
picked by priority — `gpt-image` > `imagen` > `gemini-image` > `flux` >
`dall-e`. There is no guessed fallback: if the provider has no image-output
models in the catalog, the tool fails with guidance to pass `model` explicitly,
or to add a `supports_image_output` overlay entry and run `/refresh-models`.

## The result

Generated bytes re-enter the same pipeline as `display_image`: the image is
shown inline in the client, persisted durably in the `session_attachments`
table, and can be read back with `read_image` — so the model sees its own
generation and can refine it. The tool also reports the model that produced the
image and, when the provider returns one, the provider's revised prompt.

> The credential never reaches the tool: provider resolution runs through the
> daemon command loop, scoped to the requesting session, so cancelling the
> session also aborts an in-flight generation.
