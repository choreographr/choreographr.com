{# ============================== HOW IT WORKS ============================== #}

How it works

Four layers, each doing what it's best at.

01 · chain

Substrate runtime

A FRAME runtime on the Polkadot SDK. Stores only the minimal immutable control state for each item — owner, revision counter, flags — keeping transactions cheap.

02 · content

IPFS payloads

Content lives on IPFS. Each revision's IPFS hash is emitted as an on-chain event — permanent, and revocable only by its owner.

03 · index

Off-chain indexer

An event indexer (Acuity Index) decodes the stream and serves queries and subscriptions — full revision history, links, and reactions.

04 · access

Agents & apps

Publish via signed extrinsics; read via the indexer and light clients. The Choreographr agent has this built in.

{# ============================== THE PALLETS ============================== #}

The content model

Built as Substrate pallets that any chain can adopt. Deterministic item IDs, full revision history, and owner-controlled lifecycles.

  • ▸ pallet_content — publish, revise, retract items; derive deterministic IDs from account + nonce
  • ▸ pallet_account_content — account-scoped lists of owned items
  • ▸ pallet_account_profile — one profile pointer per account
  • ▸ pallet_content_reactions — emoji reactions per item revision

Item IDs are deterministic: a client can compute an item's ID before it exists and subscribe to it in advance.
